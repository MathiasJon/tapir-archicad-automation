Maintainer review: tested live on Archicad 29 (French UI) on a copy of `Test/TestProject.pla`. This answers the open DevKit questions.

- `API_AttributeFolder::guid` is a `GS::Guid` (APIdefs_Attributes.h), so `GS::NULLGuid` is correct.
- `content.subFolders` entries come with their full path.
- **Blocking: the reported paths start with the localized name of the root folder.** Archicad returns the root folder with its own name as path, and every subfolder path starts with it. A layer in the root folder comes back as `["Calques"]` (the French UI name of the Layers root) instead of `[]`, and a nested one as `["Calques", "Design", "Architectural"]`. That contradicts the description, depends on the UI language, and cannot be passed back to the folder commands of #953/#1024, which take paths **without** the root name (`["Design", "Architectural"]` works, the prefixed path does not).

  Starting the walk from an empty root path is enough. The existing "one level below its parent" rebuild then produces root-relative paths:
