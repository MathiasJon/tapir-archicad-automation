Maintainer review: DevKit and live checks on Archicad 29.

- **DevKit:** `ACAPI_GraphicalOverride_SetOverrideRuleGroupOrder (const GS::Array<API_Guid>& orderedRuleGroupIds)` expects "the ids of all the user-defined rule groups". The AC25 failure was the transient DevKit download error (HTTP 500), so a re-run should be enough.
- **Blocking: fails on any project with the built-in Renovation group.** Moving any group in front of `RENOVATION` returns `APIERR_NOACCESSRIGHT`, and so does the example ("last group to the front"). Built-in groups cannot be moved, and the API has no flag to tell them apart. `ACAPI_GraphicalOverride_ChangeOverrideRuleGroup` with the group's own name is a no-op that fails with `APIERR_NOACCESSRIGHT` only for a built-in group. This patch keeps built-in groups in their place and applies the requested order to the movable ones. It also refuses a listed built-in group with a clear message:
